# 剪辑经验与技能提炼

采集日期：2026-10-09。目标：把实际编辑判断沉淀成按需调用的技能，并保留失败、适用条件和验证范围。

## 分析范围与证据

本次读取并梳理47份记录：16份批次清单、结构复核、口语审校、声音对比、交互记录和跨项目复盘，加中山大学31份LEAD技术复核。来源路径、指纹和行数见 [来源清单](../artifacts/skill-extraction-20261009/sources.json)。

涉及中国移动六期下29条候选、历史双段课程41条成片复盘、中山大学136条交付清单及追加17条文案缺项、数智汇骨架/精修复盘。各清单存在历史版本、复用和重剪，**不累加成独立成片总数**。136条表中的原句式标题有不少依赖指代，例如“所以它是一个光谱”“有一天你去业务部门”；这是标题独立性复核的候选信号，不能只凭标题判定视频不合格。

本次是文本与记录分析，没有逐条重新听看所有视频，没有完成新增事实核验或平台效果测量。历史报告中的“通过”沿用其检查范围，不扩大为内容质量或用户批准。

## 最有价值的发现

1. 选题不是摘金句。全片骨架、历史去重、未处理区间和问答扫描需要一起使用。候选表剪完不等于全课有价值内容已挖完。
2. 独立表达是具体编辑能力：补主语、恢复前提、选择证明观点的例子、把限制放回论断旁、找真正结尾。
3. 口语精修需要逐处判断删与留。填充词频只能召回疑点，声音实际处理、字幕更新和听感复核缺一不可。
4. 课堂问答是一条独立产出线。问题条件和说话人归属决定回答是否有效，不宜按普通单人演讲自动处理。
5. 最容易被剪坏的是观点强度：未来变现状、个案变行业规律、可能变必然、Demo变成熟成果。
6. 画面、声音、文字、技术与用户选择需要各自的证据，不能靠一个评分代表全部质量。
7. 经验必须包括反例和验证范围，防止同一段转录既用来生产又用来“证明正确”。

## 新技能的调用与输出

| 技能 | 适合何时调用 | 核心交付 |
|---|---|---|
| 全片选题与去重 | 想把长课剩余价值都找出来 | 覆盖台账、候选题、去重/合并理由和缺口 |
| 短片独立表达 | 粗剪或原句链完成后 | 问题位置、补背景/移条件/补结尾的原声方案 |
| 原声口语精修 | 结构稳定后 | 删/留决定、实际剪口、应用状态与听审范围 |
| 课堂问答剪辑 | 现场多人问答 | 说话人片段表、完整问题条件和回答链 |
| 论断与适用边界 | 有数字、客户结果、趋势或能力主张 | 论断证据台账、风险与收窄建议 |
| 成片声画复核 | 实际视频已导出 | 分层检查结果、问题时间点和对应版本 |
| 剪辑反馈沉淀 | 用户提出反馈或发生返工 | 前后案例、验证范围、反例和技能更新位置 |

典型组合：全片选题→独立表达→按需问答/边界检查→口语精修→声画复核→封面/文案→已有交付流程。用户只要求一个环节，就只调用必要能力，不新增审批或发布任务。

技能已经注册到本机技能中心；创建调用任务仍是“待Agent接单”，**不是后台自动完成剪辑**。相邻依赖需读取并记录指纹，现有任务快照仅冻结被调用技能本身，不能宣称自动冻结整套依赖。原技能更新只影响后续读取，旧任务快照保留。

## 尚不足以沉淀为成熟能力的内容

- **爆款规律/发布时机/哪位剪辑师效果最佳**：没有可比平台数据，角色定义仍有未验证样本。
- **个人词级自动删音**：已有案例与规则，但不能在没有可靠时间和真实听辨时宣称可自动无痕。
- **音乐增加完播率**：对比记录没有听感结论和流量证据。
- **自动完成全部技能与依赖版本冻结**：现有技能中心是任务队列；未建设统一自动执行器。
- **统一固定画布、字幕字数、12ms淡化、底部400px安全区**：属于历史项目参数，需要按素材和渠道重新核对。

## 接下来最能提升质量的验证

用一个案例片、一个方法片、一个多人问答片分别验证这些技能：检查同一版本的原句链、实际声音、字幕和封面文案。评价新增能力是否少了上下文缺失、口语残留、错误泛化和返工，而不是只看条数或技能数量。此处是验证建议，本轮没有重新导出这些视频。
