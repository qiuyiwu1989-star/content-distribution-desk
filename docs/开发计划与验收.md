# 内容分发台开发与验收计划 · v0.2

更新：2026-09-26。当前交付：本机可运行的管理、检查和执行平台。真实平台登录、草稿排版、公开作品回执尚未逐渠道验收，不能称为全平台发布已打通。

## 1. 产品目标与信息架构

将已经完成的内容变成可核对、可排期、可追踪的渠道任务。主路径是：成品包 → 批量安排渠道 → 编辑渠道版本 → 发布检查 → 确认与排期 → 执行 → 平台回执 → 人工核对。

七个页面：待分发、成品包、发布日历、发布记录、渠道账号、执行中心、平台规则。页面使用统一的浅色背景、深绿色主操作、平台色标识；公开发布单独确认，错误直接展示在当前表单。内容生产、视频剪辑与运营指标分析不进入这一阶段。

## 2. 输入契约

| 输入 | 必需内容 | 可选内容 | 进入渠道任务后 |
|---|---|---|---|
| 文章 | 主题、标题、正文或 UTF-8 Markdown/TXT | 正文插图、封面、备注 | 独立正文、标题、话题和附件 |
| 图文 | 标题、简介、至少一张有序图片 | 独立封面、话题 | 按勾选顺序保存；图片顺序不受上传器文件名排序影响 |
| 视频 | 标题、简介、一个视频 | 竖/横封面、话题、B站分区、视频号合集 | 各平台分别设置，建议 MP4 |

一个成品包是一份内容的原始材料集合，不限制它只能有一种格式。PDF 作为附件归档；不自动抽取正文。正文文件通过明确的“导入正文”操作更新，不静默覆盖。文章本机插图写为 `![说明](asset://附件ID)` 并选入该任务，或使用 HTTPS 图片地址。本机文件路径不能直接发给平台。

图片会校验是否能解析、记录尺寸和 SHA-256；视频当前没有编码、时长、分辨率的完整探测，只校验数量、文件类型并提示 MP4。单次上传请求最多 512 MB，含 multipart 开销。大量高清视频需后续对象存储与断点上传。

## 3. 任务分发与版本

- 任务键：成品包 + 平台账号 + 内容类型。批量创建在同一事务中完成，已有任务跳过；任一目标无效则整批回滚。
- 默认选图文全部图片、视频首个视频、首张图片作封面，均需用户预览后确认。
- 成品包修改不覆盖渠道版本。渠道版本修改清除排期和待执行批准。
- 执行批准包含标题、正文、标签、附件顺序与哈希、封面、平台设置、账号绑定和交付方式。
- 任务修订号防止旧窗口覆盖新修改；执行指纹避免相同版本重复入队。
- 一台机器只运行一个主服务进程和一个执行工作线程。禁止同时启动多个工作进程共享此数据库；分布式锁和租约属于生产化后续工作。

## 4. 平台适配矩阵

| 平台与类型 | 连接器 | 当前交付模式 | 特殊处理 |
|---|---|---|---|
| 公众号文章 | Wechatsync | 人工、草稿 | 当前浏览器账号再次核对，文章图片转存依赖扩展 |
| 微信公众号短图文 | 人工 | 人工 | 保留有序图文包；没有伪装自动接口 |
| 视频号视频 | social-auto-upload | 人工、草稿、发布 | 竖封面、横封面、已有合集 |
| 小红书图文/视频 | social-auto-upload | 人工、发布 | 图片顺序、简介和标题保守检查 |
| 抖音图文/视频 | social-auto-upload | 人工、发布 | 图文有序图片，视频独立封面 |
| B站视频 | social-auto-upload | 人工、发布 | 分区 tid、标签；上游可能在首次调用时下载 biliup |
| B站文章、知乎文章 | Wechatsync | 人工、草稿 | 扩展草稿回执，最终排版人工检查 |
| 抖音精选 | 无独立执行器 | 不建重复任务 | 从抖音发布，精选触达不作为系统承诺 |

所有自动连接均为“代码接入、待真实账号验收”，不是平台官方稳定发布 API 的保证。规则在 `platform_rules.py` 版本化，当前限制是适配器的保守输入约束，后续按真实后台核验更新。

## 5. 账号与连接

Wechatsync：安装官方扩展，启用同步桥接；把分发台显示的随机本机 WebSocket 地址填入扩展；把扩展生成的 Token 粘贴回分发台。再检查平台登录信息，核对身份后绑定。桥接仅监听 127.0.0.1，拒绝普通网页来源；没有开放 HTTP 代理。

视频/图文上传器：为每个账号设置独立标识，复制界面生成的本机登录命令，用户亲自登录，再检查并绑定。上游检查仅返回登录是否有效，无法可靠返回真实账号昵称；绑定步骤明确由用户核对正确账号。执行前校验登录文件指纹；登录检查超过 24 小时要求重查。上传器登录文件与扩展口令保存在本机，不进入普通页面响应。

## 6. 执行与异常

人工任务到期进入待交付。自动任务到期由本机队列串行执行；电脑、服务和所需浏览器必须保持运行。离线时不会执行，重启会补执行未过期批准的排期。需要严格控制过期任务的场景应先取消排期。

状态：待完善 → 已排期/等待执行 → 执行中 → 已存草稿 / 待核对 / 受阻。不会依据进程退出码直接标记“已发布”。

- 执行前检查失败：受阻，不提交。
- 扩展明确返回草稿成功：已存草稿；仍需平台排版检查。
- 上传器完成、超时、断连、结果无法解释：待核对，不自动重试。
- 服务重启发现执行中任务：转待核对，避免重复上传。
- 重试：必须记录检查草稿/作品列表、确认无重复；公开发布再次确认。
- 人工标记公开发布：要求对应平台 HTTPS 作品链接和核对说明；这是人工证据，不等于系统独立抓取验证。
- 需要改稿：核对后记录问题，再返回编辑，重新批准。

## 7. 已完成验证

自动化测试使用临时数据库与模拟适配器，覆盖输入导入、批量事务、任务重复、版本冲突、账号绑定失效、公开发布确认、取消重排、执行一次、结果未知重试、重启恢复、媒体变化拦截、WebSocket 请求响应协议与非法路径拒绝。没有用测试内容向真实平台提交。

浏览器验收使用独立数据目录：检查平台矩阵与进度页、批量创建且跳过已有任务、缺图片时禁用提交、渠道连接及执行中心。上传器六个目标命令的帮助入口已检查，安装了 Python 3.12 运行环境、依赖和 Chromium；这些不等于真实上传验收。

## 8. 后续验收顺序与完成标准

1. **公众号首条草稿**：真实账号绑定 → 含封面和本机插图文章 → 草稿存在 → 标题、图片、排版正确 → 回填草稿结果。
2. **小红书图文**：账号确认 → 多图顺序、标题字数、简介与话题 → 用户明确批准的内容发布 → 核对作品链接与公开状态。
3. **视频号视频**：先草稿验证封面与合集 → 再按用户批准验证发布 → 核对结果。
4. **抖音、B站、知乎**：各至少一份代表性内容，验证各平台规则、账号过期与失败重试，留存真实回执。
5. **生产化与主站接入**：沿用 qiuyiwu.com 主站认证与权限；使用独立路由前缀、可靠队列租约、流式文件、对象存储、服务监控、部署与备份恢复验证。保留现有主站和工作台，不另造身份体系。

每个平台分别记录：账号、连接器版本、内容样本、执行时间、平台回执、人工核对人和结果。只完成登录不算发布验收，只返回草稿不算公开发布成功。首次真实联调需要用户完成扫码/登录并选择要交付的内容；目前这一项仍未完成。
