# 微信视频号发布包规范（给内容创作 Agent）

版本：2026-10-07。适用范围：把**已经制作完成的视频**交给本机「内容分发台」，建立「微信视频号 · 视频」渠道任务。本文描述的是本项目当前的输入契约与交接流程，**不是微信视频号官方规格**；平台限制和页面行为须在实际账号后台复核。

## 交付目标

Agent 交付的是一份**待审阅的发布包**，不是一次发布授权。分发台随后由人核对账号、视频、标题、封面、文案和交付方式；提交草稿或公开发布是独立的确认步骤。不要让 Agent 登录账号、读取 Cookie、选择已登录账号或自行宣称发布成功。

## 必交文件

建议按下面的目录交付。文件名可改，但在 `manifest.json` 中的路径必须准确、相对本目录，不能指向网络地址或其他目录。

```text
视频号发布包-内容短名/
├── manifest.json        # 元数据；按下方契约填写
├── video.mp4            # 最终视频，恰好一个
├── cover-vertical.png   # 推荐：竖版封面
└── cover-landscape.png  # 可选：横版封面
```

视频文件是必需的。当前分发台接受 MP4、MOV、WebM，**建议交付 MP4**；它目前不完整探测编码、时长、分辨率或音频质量，因此 Agent 应在交付前独立播放成片，检查画面、声音、字幕和结尾。单次网页上传请求上限为 **512 MB（含 multipart 开销）**；接近上限的文件先压缩或改用后续的大文件方案。封面接受 JPG、PNG、WebP，分发台会检查图片能否解析；尺寸与裁切效果仍需在视频号后台预览确认。

## `manifest.json` 契约

以下是可复制模板。`null` 表示没有该素材；没有合集就用空字符串。不要把示例文字原样当成成品。

```json
{
  "schema": "content-distribution-desk.channels-video.v1",
  "package_title": "这份内容的内部主题名称",
  "channel_title": "面向视频号的短标题",
  "description": "视频号发布文案。说明核心观点、观看价值和必要的上下文。",
  "tags": ["AI", "教育"],
  "files": {
    "video": "video.mp4",
    "vertical_cover": "cover-vertical.png",
    "landscape_cover": "cover-landscape.png"
  },
  "collection": "",
  "review_notes": "需要人确认的事实、引用、授权、敏感信息或平台排版问题",
  "source": {
    "canonical_url": "",
    "source_title": "",
    "source_version": ""
  }
}
```

| 字段 | 要求 | 映射到分发台 |
|---|---|---|
| `schema` | 固定值，不要修改 | 交接格式标识；当前网页尚不自动读取此 JSON |
| `package_title` | 必填，内部识别用，不超过 200 字 | 成品包标题 |
| `channel_title` | 必填，**不超过 16 个字符**；这是当前适配器的保守检查值，不是平台官方上限 | 视频号渠道标题 |
| `description` | 必填，写可直接审阅的最终文案；不要把制作说明混入文案 | 渠道正文／简介 |
| `tags` | 字符串数组，可为空；写词本身，不带 `#`，不重复 | 渠道话题，导入时合成标签文本 |
| `files.video` | 必填，恰好一个本地视频文件 | 视频素材 |
| `files.vertical_cover` | 推荐，图片文件或 `null` | 渠道封面 |
| `files.landscape_cover` | 可选，图片文件或 `null` | 交付设置中的横版封面 |
| `collection` | 可选；只填**账号后台已经存在且名称核对过的合集**，否则留空 | 视频号合集 |
| `review_notes` | 可选，仅供人审阅，不发布 | 成品包备注／交接说明 |
| `source` | 可选，记录网站文章或其他原始内容的出处与版本；不等于视频已公开 | 来源追溯 |

`description` 和 `tags` 是两项独立输入。不要把话题标签拼进标题；标签可在文案中自然出现，但仍应单独给出，以便渠道任务调整。`collection`、目标账号、交付方式、排期时间和公开发布决定**不由创作 Agent 猜填**，由操作者在分发台确认。

## 内容质量与交接检查

- 视频已经导出并完整播放过；画面、声音、字幕、引用和片尾没有明显错误。建议另在 `review_notes` 说明前三秒的开场意图、需要重点核对的事实与素材授权。
- 标题与封面表达同一主题，不夸大视频没有提供的结论；标题满足本项目 16 字检查。
- 文案是可发布稿，不含“待补”“TODO”“请帮我改”等内部指令；未核实的信息明确标为待核对，不编造来源或数据。
- 封面中的文字在缩略图下仍可辨认；没有封面可以交付，但分发台会给出提示，平台可能自动取帧。
- 输出明确写出视频、封面文件路径和最终 `manifest.json` 路径；仅给脚本、预览或渲染计划不算成片交付。

## 进入分发台后的操作

1. 新建成品包，使用 `package_title`，将 `video` 和封面文件上传为附件。`manifest.json` 当前是**给 Agent 与人交接的说明文件**，不是分发台一键导入格式；需按字段手工录入。
2. 选择视频号账号，创建「视频」任务；在渠道版本中填写 `channel_title`、`description`、`tags`，选择**恰好一个视频**和竖版封面。
3. 在交付设置中选择人工交付、送入草稿或提交发布；按需设置横版封面和已存在的合集。第一次真实账号联调建议先选「送入草稿」。
4. 运行发布检查。自动模式还要求本机上传器可用、账号已登录并绑定，且账号检查未超过 24 小时。确认的版本会绑定素材哈希；之后改视频、封面或文案，都要重新检查和批准。
5. 执行后到视频号后台核对草稿或作品。上传器目前没有可靠的结构化作品回执；即使命令正常结束，分发台仍会标为「待核对」，不能据此声称已发布。结果不明时先检查是否已有草稿／作品，避免重复上传。
