## 信息关系

内容包保存通用信息与素材；渠道任务保存独立的标题、文案、选中素材及交付设置。批次与序号进入数据库，平台合集继续归属渠道设置。一个内容可以关联多个渠道，内容库汇总全部渠道。

人工内容检查与发布授权分开保存。检查基于同一 SQLite 读取快照返回的正文、素材、渠道信息及指纹，提交时再次核对。内容变化后，先前检查呈现为失效，原记录保留。新检查同时保存文本及素材元信息快照；不承诺复制或恢复旧媒体文件字节。

取消渠道安排不使内容自动作废。只有手动归档或明确关联替代内容，才从当前内容视图进入历史。相同标题仍是独立内容，系统不自动合并。

## 界面结构

- 内容库：批次、序号、全部渠道概况、具体素材缺项、连续检查。
- 发布工作台：待准备、待执行、待核对；日历作为子视图。
- 发布记录：渠道结果、已取消安排、执行历史。
- 账号与设置：渠道连接与平台能力说明。

内容详情并列显示视频、所选封面及渠道文案。渠道编辑把合集、交付方式和文案一起保存，仍会使原批准及排期失效。未保存内容可撤销，导航不会静默丢弃渠道修改。

## 数据迁移与恢复

首次库迁移前用 SQLite backup API 生成一致性备份到实际数据目录的 migration-backups。批次目录只按已存在的精确内容 ID 导入一次，不再按标题猜测。以后在应用中编辑批次与序号，静态目录不再覆盖数据库。

工作区代码和原始数据库备份保存在 backups/ux-architecture-20261008；应用更新前另备份安装目录中的受影响源码。历史执行核对只更新该执行记录，不改变当前渠道内容、任务状态，也不会再次提交。

## 范围与后续

保留现有账号加内容类型的任务唯一约束，没有重写平台连接器或引入新的自动发布路径。内容版本目前通过显式关联既有内容表达；不是自动复制媒体的版本管理器。已取消任务不能直接复活为同一条任务，历史保持原样。平台真实草稿、合集与公开发布能力需要独立平台验收。
