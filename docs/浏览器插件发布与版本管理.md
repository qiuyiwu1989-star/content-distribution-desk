# 浏览器插件发布与版本管理

入口：创作资源 → 浏览器插件。机器可读目录：`/static/browser-plugins/catalog.json`。

源码在 `extensions/channels-assistant/`。可下载版本在 `static/browser-plugins/releases/<插件标识>/<manifest版本>.zip`。catalog 指定 current_version（推荐下载），保留全部历史版本、更新说明、包大小、归档时间和 SHA-256。

当前已归档 0.6.1、0.6.2、0.6.3、0.6.4、0.7.0、0.7.1、0.7.2、0.7.3、0.7.4、0.7.5、0.7.6、0.7.7、0.7.8、0.7.9；推荐 0.7.9。归档时间表示收进版本中心的时间，不冒充原始发布日期。更新说明来自现有 README；未找到详细说明的历史版明确标为历史归档。

## 以后修改插件时

1. 修改源码，并提升 manifest.json 版本号；保留旧版本包。
2. 完成对应的 Node 回归与语法检查；真实平台效果单独记录。
3. 写本版更新说明到文件，明确修复、功能与仍待核对的情况。
4. 用统一脚本发布。脚本验证 manifest、引用文件和版本号，为包记录 SHA-256；同版本不同内容拒绝发布，多 Agent 发布使用文件锁。

```sh
.venv/bin/python scripts/publish_browser_plugin.py \
  --id channels-assistant \
  --source extensions/channels-assistant \
  --notes-file /绝对路径/本版更新说明.txt \
  --recommend --install-local
```

--install-local 会把版本目录与发布包同步到本机已安装的分发台，并备份原目录清单。同版本不同内容仍会拒绝覆盖。首次入口的 JS/CSS 已安装；修改管理界面时另行部署这些静态文件。安装包制作时也要包含此目录。推荐版本指针可通过同包、同说明重新执行 --recommend 切换；ZIP 不会覆盖。发布失败时目录保留原推荐版本，不通过伪造更高版本解决问题。

已解压安装的 Chrome 插件不因下载 ZIP 自动更新。用户需要更新原插件目录中的文件并重新加载，确认浏览器显示目标版本。换用其他目录可能形成不同的插件实例；保留原目录与本机数据再操作。

当前下载入口在本机。外部人员直接访问需随分发台部署共享下载服务；本次没有开放本机业务服务到公网。可先发送本页下载的 ZIP。
