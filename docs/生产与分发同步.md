## 当前职责

生产端保留工程、原片、修改过程及最终成片；分发端保留可独立使用的成片、封面、渠道文案与发布结果。插件按需读取分发端素材，本代码没有另建持久视频库；浏览器临时缓存及平台存储不在本次盘点内。

新上传在分发端按文件大小与SHA-256匹配，内容相同则使用硬链接共用物理文件，保留独立素材ID与版本引用。链接不支持时回退普通副本；不改变生产原件，不回收旧重复文件。所有素材必须不可原地修改，更版生成新ID。

## 以后如何同步

生产端既有入口：协作资料/工具/审阅工作台/导出发布包.py 和 导入分发台.py。前者输出batch.json与逐条manifest，后者创建分发内容与渠道任务并回写dispatch_snapshot/dispatch_history。不是自动监听文件夹。

统一入口（从本项目目录运行）：

```sh
python3 scripts/sync_production.py --batch <批次ID> --only <序号>
python3 scripts/sync_production.py --batch <批次ID> --only <序号> --apply
```

省略only时同步该批次默认可导出的已完成内容；不会调用包含未审内容的export --all。默认会更新生产发布包，但只预演分发导入。--apply才写分发库。账号默认沿用既有导入器配置，也可--account指定；非默认发布包目录用--pkg指定。

同版本已有回执自动跳过。内容更版不能静默覆盖旧任务；既有导入器的--new-version用于明确另建版本，统一入口不默认启用它。当前导入器不是跨进程原子事务，网络中断且回执未写回时仍需核对半完成导入，不能承诺完全幂等。

生产工具可以在“最终导出完成”之后调用上述--apply命令。当前已提供命令衔接，没有改动生产工具界面的导出按钮，也未开启无人值守监控。未执行真实批次同步，避免把现有85条再建一遍。

## 简化后的发布

选内容 → 插件同步 → 在平台发布 → 点击已发布。工作台不再要求人工交付批准；复杂旧执行入口收在高级。人工确认与平台自动观察分开记录，标错可撤销；旧版本发布历史不会抹掉，新版本重新出现在待发布。
