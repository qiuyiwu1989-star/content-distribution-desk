# 原声观点视频封面设计

让观众一眼看懂这条视频值得看的观点，并能在视频里获得封面承诺的内容。交付实际可用的封面图片、原始生成图及可复用提示词，不止给提示词或设计建议。用户只要方案或评审时，按其范围交付。

## 接住剪辑工作

优先读取当前项目的内容记录、选题策划、最新版成片、字幕及审核意见。与 course-video-editing 协作时，按其 `references/content-record.md` 和 `references/publishing-package.md` 读取真实接口；独立使用时直接读取用户提供的视频与文稿，不要求安装该技能。

每条明确 clip_id、视频路径、render_revision、核心观点与目标受众。只处理本次指定批次。没有成片时可依据已确认策划做概念稿，标明“基于策划，待成片核对”。缺少观点依据时不编造内容；先检索现有转录，确实缺失再询问必要材料。

标题依据必须落在本条成片实际保留的内容中。记录支持它的原句、原片时码及可用的成片时码，区分两个时间基准。只有 ASR 证据时明确尚未听音核实；不要宣称已完成听审。引用已有审核结果必须核对对应版本。

## 文案决策

先用一句话写出“这条视频回答什么问题”，再拟封面标题。默认给 3 个有区别的候选：直接观点、受众问题、被原声支持的反常识角度；没有反常识依据就换成具体收益，不硬造冲突。选出推荐项并简述依据，直接制作推荐稿，不为普通设计选择反复等待确认；推荐不等于用户已选定。

封面主标题、平台短标题、视频内标题分别记录。默认主标题尽量 8–16 字、2–3 行，每行构成完整短语；这是设计起点，不是平台限制。数字、否定、条件和因果不能为了短而删掉。没有逐字证据的概括不加引号，不把设计文案冒充讲者原话。不增加“唯一”“必然”“所有人”等原声未支持的承诺。

默认不把姓名、职务、课程全名、话题标签同时堆到封面。需要系列名时降为次级信息。实际平台限制通过当前官方说明核实，不把项目字数偏好称作平台规则。

## 模板库与调用

用户选择模板时读取 `templates/catalog.json` 中对应 ID、版本、规则和示例；模板决定字体、颜色、质感和布局范围，主体与文字依据当前成片重新设计。逐项读取 `text_rules`（主标题、问题、断行、强调、图注、元数据、禁用表达）与 `migration`（保留、替换、适配），不只看缩略图。新增样张基于现有内容记录，属于设计候选，不能冒称经过听审或点击率验证。模板的 `style-confirmed` 只代表风格已确认，`design-candidate` 仍为候选。不要把示例里的讲者、地点、日期、数字或课程自动写入新封面。

模板库现有34套，覆盖概念插画、文字判断、同尺度对照、工艺拆解、路径门槛、双声部、知识索引、证据透镜、决策轨道、任务边界、双流协作、专家环绕与折页框架。具体 ID 与构图变体以目录为准；在分发台「创作资源 → 封面设计」查看、复制调用要求或为内容保存选择。

调用例：`使用 $video-cover-design，模板 COVER-FOREST-ISO@1.0，为 T15 的当前成片设计封面。` 从 `/api/packages/<package_id>/creative` 读取 `cover_id` 与 `versions.cover_id`，从 `/api/creative/catalog` 解析模板；选择模板不代表图片已经生成。服务不可用时读本技能的目录。记录 template_id 与 template_version，适配本条内容而非机械换标题。

本模板库主稿采用3:4、1080×1440；用户另指定比例时重新构图。本用户的封面统一用图像模型直接生成包含标题和画面的完整图片，不使用 SVG、HTML、Canvas 或代码绘图替代。保留参考图、提示词和栅格原稿，不称作分层源文件。用户指定模型时优先使用该模型；工具未暴露型号或模型选择时，如实说明实际调用工具与无法核实的版本，不假称已使用指定型号。

## 视觉起点与实现

优先延续本批次已选样式；没有参考时，先依据观点选择文字主导、人物侧置、调查拼贴、漫画叙事、单物件隐喻、纪实场景或同尺度对照，确定观看顺序后起稿。这是可调整的初始方案，不能写成用户已批准的品牌规范。

可根据内容选择：

- **真实人物与观点**：从指定成片或可追溯原片选自然、清晰的讲者画面，保留人物比例，不默认推近脸部。
- **观点与关系图**：适合组织、流程、对比等主题，用少量形状表达视频里真实存在的关系。
- **概念插画与观点**：抽象主题确实受益时使用；插画是说明，不伪装成现场照片、真实案例或数据证据。

封面可以单独构图，不强行复制视频中“上标题、中横片、下字幕”的所有层次；保留系列识别。优先选择无半句字幕干扰的画面，用布局遮罩或换帧解决干扰，不随意涂改原片证据。检查闭眼、嘴型、遮挡、人物拉伸和敏感信息。原片有脱敏要求时，封面也必须覆盖。

默认主稿与当前竖版成片同比例、同像素尺寸；尺寸无法确定时可先做 1080×1920 的设计稿并注明假设。需要横版或方形时重新排版，不拉伸。没有平台裁切信息时，把四周约 8% 作为保守设计留白并做居中裁切预览，明确这不是平台安全区认证。

工具按实际能力选择：

- 真实视频截帧用本地视频工具，记录精确视频来源和截帧秒数；中点附近只用于寻找候选，不是选帧标准。
- 新生成或编辑栅格插画时使用可用的图像生成工具，并先读取对应 imagegen 技能；遵守其编辑与参考图要求。不把未经检查的生成文字直接当定稿。
- 标题、问题、插画和整体构图通过图像模型整图生成；修改文字或构图也用图像编辑工具。普通尺寸导出可以缩放，不重新用代码画图。
- 图像工具不可用时保留方案并说明阻塞，不退回 SVG 或代码绘图，不把源代码称为生成图片。

批量任务先做一条代表性样稿和手机缩略图预览，建立同批次的字体、色彩、间距与系列标识。用户已授权整批制作时可采用推荐样式继续，不新增审批门槛；对每条内容单独提炼观点，避免只换标题的机械套版。


## 差异化方案评审

多风格探索先研究差异明显的实际作品并记录来源、观察及迁移边界；不把他平台尺寸或营销点击率说法当视频号规则。研究记录见 templates/差异化研究.txt。

比较至少四个维度：图片语言（摄影、拼贴、漫画、文字）、观看顺序（文字先、主体先、并行、对话）、构图（左侧、中段、下方、满幅）、字体与色彩。只换主体、颜色或标题不算新风格。可固定一条真实内容和同一标题做6套探索；多变量探索不是严谨单变量A/B测试。

最小信息为一个观点标题、一个视觉焦点和清晰层级；问题小字、系列、日期和署名都可选。180px宽先读懂主标题和主图；不要为了信息多牺牲阅读。个人封面优先考虑真实讲者素材，禁止生成本人替身；概念摄影不冒称真实案例。

新方向 COVER-TYPE-PUNCH、COVER-REPORT-COLLAGE、COVER-COMIC-TENSION、COVER-SINGLE-METAPHOR、COVER-DOCUMENTARY-BAND、COVER-DUOTONE-CONTRAST 保留各自图片语言与观看顺序，不统一成米白宋体立体模型。库内可有多个系列；系列内部保持识别，整个库保留差异。正式同尺度比较必须检查物件尺度，巨字必须检查字形与边距。


## 能力与提示词资源

读取 templates/能力与提示词研究.txt 区分实际验证、案例启发和未测试能力。每套的 prompt_template 是含占位字段的中文通用提示词；generation_prompt 保存本次实际输入，不能把历史标题直接用于新片。先以当前成片填入主题、依据、受众、文字、对象与构图，再调用图像模型。

提示词写成可读设计要求：用途与受众、观点依据、准确文案、主体关系、媒介材质、构图留白、必须保留与禁止增加的元素。分镜逐格写动作并锁定跨格对象；局部修订明确只改哪里和保留哪里。写明不等于必然满足，输出后必须检查。

用户认可漫画与红底单物件的方向；可以继续扩展这两类，但其确认不代表所有新变体已通过内容审核。借鉴他人提示词的机制，保留来源，不抄作品或新增示例事实。

## 封面测试与剪辑反馈

导出后必须打开实际图片检查，再检查约 180 像素宽的缩略图；需要时做方形/横版裁切预览。逐条核对：

1. 缩小后仍能读懂主标题，断行自然，重点没有被背景吞没。
2. 标题承诺由本条成片支持，画面和概念不制造额外事实。
3. 人物自然，中文无错漏，比例正确，关键内容不被裁切，敏感信息未重新暴露。
4. 封面与视频对应正确版本，审核入口指向实际图片。

视觉检查不等于用户批准或点击率验证。A/B 设计只更改一个主要变量，例如标题角度或人物/图解布局；没有实际曝光与点击数据，不宣称哪张效果更好。数据比较说明观察窗口、样本量、渠道及其他差异。

若封面承诺无法由视频兑现，优先收窄封面文案；把需要剪辑补足的事项回传为建议，不自行改视频。原声、结构、标题或脱敏版本改变后，将封面标为待复核；核实仍匹配才恢复可交付状态，不要求无意义重画。

## 保存、审核与交接

使用稳定 clip_id 和独立封面版本保存，例如 `covers/<clip_id>/c01/`，保留历史。每条交付主图、原始生成图与提示词、缩略图预览和简短设计记录。批次优先嵌入现有审核台；无法接入时提供一个联系表预览入口，不声称已经集成。

设计记录至少包含：clip_id、render_revision、封面版本、观点证据、标题候选、推荐标题、用户已选标题（未选留空）、图片/源文件路径、像素尺寸、截帧来源与时间（非截帧留空）、视觉检查结果、用户确认状态。沿用项目已有字段，新增内容放在相邻设计记录中，不擅自改变主记录 schema。

候选稿不覆盖主记录的选定封面。用户选定或已授权自动选定后，更新现有 `cover.path` 以及实际存在的交付 manifest 引用，保留未知字段和历史值；若原记录使用 sha256，同时刷新图片哈希。`cover_capture_seconds` 只记真实截帧时间，且来源另行说明；纯设计图留空，不伪造时间。平台短标题不因封面文案变化而自动覆盖。

交付区分“方案 / 图片已生成 / 视觉已检查 / 用户已确认 / 已写入交付包”。创建封面不授权发布或上传平台；无平台回执不能声称封面已应用。总结给出实际预览与唯一审核入口，并指出仍待核实的项目。
