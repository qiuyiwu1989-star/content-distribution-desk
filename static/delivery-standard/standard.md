# 内容交付标准 1.4

标准文档版本：1.4。数据格式版本：distribution.delivery.v1。补充内容质量、原声精修、封面、审核证据与学习回流；不改变现有导入字段。

内容先入库，账号在下派时选择；内容默认可分发，人工可打回修改。

“默认可分发”是工作台的流转规则，不是自动质量验收结论。未听审、封面未核查、事实疑点等仍要如实记录；不能把这个标签写成“人工审核通过”。

适用：课程视频、封面设计和其他生产 Agent 向内容分发台交付。首批实例：中山大学 MBA 分享。

## 最少需要交付什么

一份 UTF-8 `batch.json`，以及清单引用的当前素材。最终交付还包括 `delivery-quality.json`（质量与来源记录，结构见下文）及最终成片时间轴字幕；未完成项如实写入 issues。JSON 是机器读取的权威清单；Markdown 可作阅读说明，不能另存一份不同的发布正文。不要交付密码、验证码、浏览器会话或平台登录凭证。

批次字段：
- `schema`：固定 `distribution.delivery.v1`。
- `batch_id`：稳定批次标识。本批 `sysu-mba`。
- `batch_name`：显示名称。本批“中山大学 MBA 分享”。
- `created_at`：带时区的导出时间。
- `items`：内容条目数组。

条目字段：
- `content_id`：全局唯一、终身稳定。例如 `sysu-mba/085510-A-1`。不得用标题、显示序号或文件路径作为身份。
- `sequence`：本批排序，正整数、批内不重复。
- `revision`：交付版本；本次适配器使用条目除 revision 以外字段的规范化 JSON 的 SHA-256。
- `title`：内容名称，用于库内识别。
- `short_title`：独立的平台短标题（当前工作台视频短标题字段上限 16 字符，含空格；不是所有平台的通用限制）；画面、封面标题不能擅自覆盖此字段。省略时首次导入沿用 title；沿用的标题仍须检查能否独立成立。
- `body`：纯文本正文。不带 Markdown 加粗符号，不重复附加 tags 中的话题。
- `tags`：字符串数组，不带 `#`。发布时由插件统一拼接。
- `assets.video`：唯一当前发布成片；暂缺时为 null。
- `assets.cover`：唯一当前封面；暂缺时为 null。不同尺寸可在未来扩展 variants，不能让插件随机选图。
- 每个素材记录 `local_path`、`sha256`、`bytes`。这是本机引用模式；路径必须真实存在，指纹由程序计算，不能由 Agent 编造。
- `source`：原片 film 编号与生产清单路径；记录本条视频、正文、封面的来源。
- `issues`：客观缺失或待核查情况的字符串数组；没有则为空。
- `publication_state`：生产交付固定为 `unpublished`，不表示平台发布结果。

便携文件包可使用相对路径，但当前适配器只支持 local_path 绝对路径。制作可跨电脑的 ZIP 时，应由转换器改成包内路径，并校验路径不能越出交付目录。不要把绝对路径当作云端素材地址。

## 发布标签规范（本次明确要求）

每条至少 10 个不重复标签，必须精确包含 `造物云` 与 `FDE`。这是本项目内容规范，不是视频号平台强制规则。“造物员”为此前口误，正确名称是“造物云”。两个必含标签的位置不固定，优先让具体主题标签靠前，按内容自然穿插；不靠重复标签凑数量。

剩余至少 8 个标签结合该条正文、标题或原声材料选择。优先保留原有相关标签，补充具体主题、行业、方法或适用场景；不要把所有视频套上同一组泛标签，也不要从标题推断未经材料支持的事实。原有正文缺失的条目仍需补正文，标签齐全不代表可以发布。

JSON 的 tags 使用不带 #、无空白的独立字符串数组；界面展示时才拼成 `#标签`。英文多词标签应规范化，例如 `AI Agent` 为 `AIAgent`，避免被插件拆开。正文不重复携带同一组话题。

例如第 8 条：`造物云、FDE、AI转型、产品型工程师、业务、组织、业务理解、产品化、AI工程师、业务与技术`。

导入前自动校验数量、必含项和标签格式；校验失败返回具体内容 ID，生产 Agent 修正后重交，不增加用户逐条确认步骤。本次适配器已加入这项校验；分发台所有入口的统一校验尚未实现。

## 视频与图片怎样对应

剪辑 Agent 和封面 Agent 使用同一个 content_id。封面交付必须含 content_id、图片指纹、实际尺寸、版本和制作状态；不要只写“第 1 条”。

本批旧封面清单只有 sequence，因此首次迁移用审阅台 manifest 的 sequence → source.film 对照，固定保存到 batch.json。后续生产直接沿用 content_id，避免重新排序后错配。

本批采用成熟纸感 c01 的新封面，不用旧封面填补尚未生成项。图片已生成不等于已逐张审阅；这种状态保留为“新封面待视觉核查”。本标准不把 3:4 宣称为所有平台的强制尺寸。

上面的 c01 是已对接批次的选定方向，不自动套到其他批次。新批次按用户选定的模板制作。当前 3:4 封面需要独立构图，不能简单裁切竖版视频；如果本次只要主题，就不额外堆课程名、姓名、日期、序号和职务。方案样张、用户选定稿和当前交付封面分开记录，未选定的 A/B/C 样张不能随机成为当前封面。

内容入库不等于下派任务。下派视频号任务时需要视频、正文、封面。缺项可先进入内容库，不能假装完整。图片素材本身不单独生成一个发布任务；纯图文内容需要另外定义图文格式与有序图片列表，当前适配器不支持。

## 更新和防重复

相同 content_id + revision 重送：跳过，不新增内容或视频。
改封面：保留 content_id，只替换封面引用和交付版本；不复制视频、不清空发布记录。
改视频：保存新素材版本，明确指定新的当前成片，历史发布继续引用当时的素材。
已发布记录只能由分发端保存；生产同步不能把已发布改回未发布。

当前试导入脚本已经支持同版本回执跳过和部分失败续传；对变更版本会停止并要求走更新流程，尚未实现自动更新已有条目。不要为绕过它而更换 content_id。接口超时后先按内容标识和回执核对，不能盲目新建。

## 本次执行方式

`import_batch.py --prepare`：从当前生产包读取标题正文，用 film 匹配视频、用审阅台顺序匹配新封面，校验素材并生成固定快照。不会写分发台。

`import_batch.py`：预览。

`import_batch.py --sample --apply`：导入第一条。

`import_batch.py --apply`：导入完整快照；已完成的同版本条目跳过。

本适配器只服务本批。所有内容先入库，不要求存在账号，不创建渠道任务。需要分发时由用户选择平台和账号；已经发布的内容可直接登记实际账号、时间和作品链接。不将批次名擅自写成平台合集，不排期、不提交平台、不自动确认审核通过。正式通用导入 API/MCP 仍需后续实现。

批次库回执 `receipt.json` 保存内容 ID → 成品包 ID、视频/封面素材 ID、任务 ID 的对应关系。每步写入后更新回执。导入前保留数据库备份 `before-import.sqlite3`；该文件含本机业务数据，仅留本机，不作为给其他 Agent 的标准模板发送。

## 推荐给后续 Agent 的任务要求

以同目录 index.json 的 agent_prompt 为可复制要求；以下质量规范同样适用。质量记录不改变 distribution.delivery.v1 既有字段，当前导入器尚未自动读取质量附录。

## 审阅台字幕交付

每条建议同时提供成片时间轴字幕：`cues: [{a: 0.0, b: 3.8, t: "字幕原句"}]`，a/b 单位为秒，必须是最终成片内时间，不是原始长视频时间；另带 total（成片时长）、content_id、video_sha256。视频版本改变时须重新交付匹配的字幕。

本批已把审阅台 136 条时间轴保存为内容附件 `review-cues-v1.txt`（UTF-8 JSON），并关联分发台 video_asset_id。新审阅模式右侧读取此附件；无字幕显示缺失，时长明显不符时禁用跳转。字幕是审阅辅助材料，不替代发布正文或人工听审。

## 内容库内直接修改

用户可在内容库编辑短标题、正文、标签并保存。新下派任务使用最新保存版本；继承通用文案的未执行任务同步更新。独立渠道文案、已发布与执行中版本保留。插件已加载的旧内容需刷新并重新同步到平台。生产 Agent 重交时应检查库内编辑，禁止用旧生产文案覆盖用户修改。

## 内容质量：陌生观众能否独立听懂

每条先写清“回答谁的什么问题”和“观众看完应记住哪一个点”。选题标题是提炼，不能冒充讲者引文；没有原声依据不编造反常识、收益、数字或结论。

- 开头直接进入问题或观点。出现“这个、他们、第二个、刚才说过”等依赖课堂上下文的表达时，补回必要原声背景，或收窄选段与标题。
- 形成完整的观点—解释／案例—落点。结尾说完，能够回应开头，不停在半句话、未展开的条件或新话题起头。
- 跨段重排检查主语、时间、因果、前提、否定和个人立场。未来设想不能剪成已经实现，局部案例不能包装为普遍结论。
- 先把选句链连起来读，再回听实际成片。文本连贯不能证明声音自然，字幕或发布文案也不能替声音补上缺失的论证。
- 聚焦一个点，篇幅由完整意思决定。能用一至两分钟讲清就不拉长；复杂案例保留必要细节，不为了固定时长破坏原意。
- 整批交付附覆盖说明：原片实际时长、已扫描范围、候选／已制作范围、遗漏与未转录区间。未被选中不等于没价值，条数不能证明全片已经挖完。

## 原声与口语精修

先剪结构，再剪口语，最后同步字幕。重复起音、失败起头和没有语义作用的口水词，应在音轨里处理；只把字幕改顺不能称为完成口语精修。

不使用全局删词规则。“就是、比如说、但是、叫做”等可能承担定义、举例或转折；否定、条件、因果、数字、时间限定和有意义的停顿必须保留。切口依据发音和停顿，回听整句及前后句；没有可靠词级定位与听辨时保留整句，列出未完成项，不假装已精准切词。

三类问题分别记录：ASR 识别错误听辨后改对字幕；本人口误核对上下文，选择可用原声替换、保留并说明或交用户判断；口语冗余处理真实音轨。不能把疑似 ASR 拼写直接当成事实，也不能用书面字幕替换没说过的意思。

## 字幕、画面、声音

字幕以最终音轨为准，保留关键语义，专名结合原声、PPT与上下文核对；不能确认的词列为疑点。交付可编辑 SRT／ASS 和审阅 cues，分别记录来源与成片版本。重排、变速或音轨变化后重新映射时间；a/b 不得为负、倒序或超出成片，非必要重叠和空档需解释。

采用本次选定的视觉模板。课程默认以主题标题、居中原横片、下方字幕建立层次；视频窗口全宽或小圆角按选择，不默认数码推近讲者，不额外堆底部身份字幕。手机尺度检查标题断行、字幕、PPT细节与遮挡；材料里的敏感信息在视频和封面上同时处理。

实测尺寸、编码、帧率／PTS、色彩、像素格式、音频格式、响度与峰值。保留源素材质量，不拉伸人物、不把放大到 1080p 当作恢复细节。可变帧率视频检查实际时间映射及长段字幕漂移；目标参数来自本次项目配置，未检测的参数不能填写“通过”。

人声清晰自然，接缝无明显吞字、爆音、突变或断尾。默认原声；背景音乐和转场音由内容与节奏决定，先试听，不固定每段加音效、不遮盖讲者、不用庆祝音效把试验包装成成功。声音素材记录来源和可用范围。

## 封面与发布文案

封面标题、视频画面标题、short_title 分别记录。封面承诺必须由当前成片兑现；数字、条件与限定不能为了吸睛而删掉。封面交付包含实际图片、可修改源文件、像素尺寸、版本、用户选择状态，以及约 180 像素宽的缩略图检查。

若用人物，选自然清晰的真实画面，排除闭眼、遮挡、异常嘴型与拉伸；记录准确截帧来源和秒数。纯设计图或生成插画不填虚构截帧时间。插画表达概念，不冒充现场照片或真实数据。样张与正式封面保持清楚对应关系。

body 面向读者，可提炼为易读的公开文案，但不加原声未支持的主张。首行给出具体观看理由，避免与下一句重复；不靠虚构冲突吸引点击。标签按本批规范和逐条内容选，不混入正文。客户提示、制作指令、听审缺项、疑似错误等放 issues／质量记录，不放进公开正文。

## 审核证据与真实状态

质量记录分别保存技术检查、语义／独立观看检查、听审、封面视觉检查和用户选择／审核。每项绑定当前视频或封面版本、审阅者、时间、覆盖范围和问题。

解码、抽帧、文字相似度、ASR重识别、播放命令都不能替代完整听审。听审 coverage 为 none／partial／full；只有确实完整听过当前版本才能写 full。声音或结构改动后旧听审保留为历史，不沿用为新版通过。封面或文案修改后，复核它们与视频的对应关系。

源／方案 → 已剪辑 → 已导出 → 技术检查 → 完整听审 → 用户批准 → 本机入库 → 本机安排 → 平台草稿／审核／定时 → 公开发布，是不同层级的观察结果，不能相互代替。已入库、已选账号或本机排期不能作为平台回执。平台结果绑定实际账号、作品与对应版本。

审阅入口保持一条内容一个当前版本：左侧片目，中间实际视频，右侧成片时间轴字幕，下方文案、文件信息和反馈。按时间点记意见，打回修改可恢复，状态持久化；策划、导出清单与分发引用同一份当前记录。

## 质量附录与文件规范

推荐目录：batch.json、delivery-quality.json、交付说明.md，以及逐条 content_id 对应目录中的 video.mp4、cover.png、captions.srt／captions.ass、review-cues.json、edit-plan.json 和封面可修改源文件。文件名可读且带批次／序号；身份与排序仍以 content_id、sequence 为准，不依赖从文件名猜身份，也不将批次名写成平台合集。

batch.json 保持现有导入格式；质量附录使用 distribution.delivery-quality.v1，按 content_id 关联，示例见 quality-example.json。记录：

- batch_id；真实源片信息、实际时长、覆盖范围和未确认缺口。
- 当前 video_revision、video_sha256、cover_revision、cover_sha256，与 batch.json 所选文件一致。
- 受众问题、核心观点、选段毫秒区间和源时间 → 成片时间映射；区间属于哪一源片写清楚，不能混用两个时间基准。
- 选定 template_id、editor_id、调用 skill_id 与内容指纹；保留已选和建议的区别。
- 技术、语义、听审、封面、用户审核记录，以及具体问题、修改意见、未完成项。

没有实际数据的字段为 null／pending／none，不编造 hash、源时长或检查结果。示例文件仅示范结构，没有真实素材，不可直接作为已完成交付导入。当前附录供 Agent 与人工复核读取，未实现统一自动校验或在所有导入入口展示。

source_segments 的每项为 source_id、start_ms、end_ms；timeline_mapping 的每项为 source_id、source_start_ms、source_end_ms、output_start_ms、output_end_ms。普通连续拼接可这样记录；复杂变速、交叠或混音需另外记录实际映射方式，不伪装为简单拼接。

技术、语义、听审与封面检查使用 pending／pass／fail；user_review 使用 pending／approved／changes_requested。时间带时区。技术 measurements 写实际测量值；没有工具测量就留空。选题 evidence 记录支持标题或观点的原句、源片时码与对应成片时码；只有 ASR 依据时写 asr-only，不称为听音核实。

## 反馈与下一轮学习

每次修改关联内容 ID、旧／新版本、问题位置、用户原意见、采取的修正和实际复核结果。口语库与 ASR 错误库收录有证据的案例，不变成一律删词或一律替换规则。

经验写回当前项目的共享技能参考资料，并说明适用条件、验证范围与来源；不由一次成功推成通用硬规则。没有用户要求不修改全局记忆。

发布后记录渠道、发布时间、观察窗口和实际指标；按内容、标题、封面、节奏评估。无曝光、点击或完播数据不宣称某个模板更有效，不把不同渠道或不同窗口的数据直接归因于剪辑。

## 内容与发布任务的归属

内容工作台保存名称、独立短标题、正文、话题、当前成片、当前封面、字幕与附件。平台账号不属于内容的必填字段。发布工作台保存渠道任务、实际账号与结果；渠道特殊文案可独立保留。单条导入可在内容工作台填写完整字段并上传素材；批量 Agent 交付继续按批次清单和既有适配器导入。

导出当前内容生成包含 batch.json 和素材的 ZIP；storage_profile=portable，素材 path 是 ZIP 内相对路径，附真实 SHA-256 与文件大小。导出同指纹素材只写一份文件。处理该包的 Agent 应先解包、解析相对路径，不直接将 path 当成本机绝对路径。导出不依赖渠道任务或账号；当前页面单条导入不自动解析 ZIP。
